**What it does**
- **Splitting** ([markdown.py](apps/ontology-builder/src/ontology_builder/sources/markdown.py)): each paragraph, list item, blockquote or table row becomes one source unit, parsed with markdown-it-py.
  - A nested list item is its own unit; a blockquote is one unit with everything inside it.
  - A table row's text pairs each cell with its column name, e.g. `Pet: dog | Max: 2`.
  - Code blocks and raw HTML are skipped.
  - Each unit records its heading path, its position in the section and its line range.
  - Text is normalised (Unicode NFC, whitespace collapsed) before its SHA-256 hash is taken.
- **Registry** ([registry.py](apps/ontology-builder/src/ontology_builder/sources/registry.py)):
  - `read_corpus` reads a folder of `.md` files, including sub-folders, and gives every corpus, document and unit a newly minted ID.
  - A document's title is its first heading, or the file name if it has none.
  - `next_corpus_number` hands out corpus folder numbers `00`–`89` and refuses a 91st corpus.
  - `CorpusSource.write_to` writes the registry. It takes any object with the store's three write methods, because the plan doesn't let `sources` depend on `store`. Ingestion will pass in the store's files object in T10.
- **`with_text`** gives a unit new text and a new hash but keeps its ID (AC-5). T13 will reuse it for revisions of user statements.
- I added the dependency `markdown-it-py==4.3.0`, the version already in `uv.lock`.

**Tests** ([test_sources_registry.py](apps/ontology-builder/tests/test_sources_registry.py)): these cover AC-4 and AC-5 using the real dog manual and building rules.
