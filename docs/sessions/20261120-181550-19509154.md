## What the template gives you

**1. A monorepo of loosely coupled apps**
- `apps/<app>/` holds each application: its own `CLAUDE.md`, `.env.example`, specs, architecture notes and decision records.
- `libs/<lib>/` holds shared code. Apps may use it only through the entry points it declares.
- `libs/contracts/<dataset>/` holds the contract for each shared dataset: who owns it, its format, schema and version.
- `docs/architecture/components.json` lists every app, library and dataset, and who may depend on or read what.
- `tools/monorepo/system-map.sh` checks those rules (no app imports another app, no cycles between libraries, every folder listed). It also draws the system diagram in `docs/architecture/architecture.md`. It runs in pre-commit and CI.

**2. A spec-first workflow (the slash commands)**

| Command | What it does |
|---|---|
| `/idea <text>` | Saves your idea word for word in `docs/ideas/`, with a log of every question asked about it |
| `/spec` | Turns an idea into a spec, at system level (`docs/specs/`) or for one app (`apps/<app>/docs/specs/`) |
| `/plan` | Writes a plan for building the spec |
| `/implement` | Builds the code from the plan |
| `/review-spec` | A separate reviewer agent checks the code against the spec's acceptance criteria |
| `/adr` | Records an architecture decision |
| `/scaffold app\|lib\|dataset <name>` | Creates an app, library or dataset from the skeletons, registers it and redraws the system map |
| `/arch-metrics` | Measures complexity and coupling and saves the results |
| `/add-language` | Adds a language's quality gate (linters, boundary rules) before the first code in it |

**3. Layered configuration**
- The root `.env` is the base, and `apps/<app>/.env` adds or overrides keys.
- If a key is set in more than one place, the process environment wins over the app `.env`, which wins over the root `.env`.
- `tools/env/with-env.sh <app> -- <cmd>` runs a command with that app's settings. Add `--check` to list missing keys.

**4. Security for a public repo**
- Pre-commit and CI run gitleaks (a secret scanner), shellcheck and zizmor.
- Dependabot keeps dependencies updated.
- `tools/bootstrap-github.sh` turns on branch protection.
