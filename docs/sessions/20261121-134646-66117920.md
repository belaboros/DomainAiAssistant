The draft spec is at [docs/specs/0002-ontology-builder/spec.md](docs/specs/0002-ontology-builder/spec.md). Summary:

**Scope:** `system`. It adds a new app `ontology-builder`, a new committed dataset `data/ontology-pets-and-house-rules/`, and a contract for `00_sources/` and `03_release/`. It reads the manuals dataset without changing it. No `libs/` library yet.

**Goals:** build an ontology from Markdown corpora and statements people type in. The LLM proposes elements and levels, people review and approve them in a local GUI, every element traces back to its evidence through stable IDs, and there are two releases (raw and governed), each with Turtle plus `level-1/2/3.md`.

**Must-haves (38 FRs, 33 ACs):**
- An ontology needs a scope record before anything can be ingested. Sign-in is just a typed handle plus a role, and the GUI enforces the role.
- **Ingestion:** Markdown only, several corpora per ontology. Every source unit gets an opaque stable ID and a content hash. The user sees a cost estimate and confirms before the LLM runs. An interrupted run leaves no partial records.
- **Extraction:** statements, terms, concepts, relations, rules and properties, each with evidence. The LLM proposes synonyms and senses (so the "lead" rope and the "lead" role are separated), a level for every element, and which passages are ignorable. Nothing is extracted from an ignorable passage.
- **Review GUI:** evidence is shown before the LLM's proposal. It has bulk actions, filters and search, status shown by colour and label, and authoring of user statements and elements.
- **Governance:** six statuses. Editing an approved element sends it back to review. Approved elements are deprecated, never deleted. Every decision is logged, and each save is one local git commit with no push.
- **Releases:**
  - The raw release is rebuilt on every save. The governed release is built when the admin publishes, with a semantic version and a change log.
  - The governed build fails if an approved element depends on one that isn't approved.
  - Levels are cumulative, and building twice gives identical output.
  - Each release has OWL cardinality plus SHACL, SKOS labels, and Mermaid diagrams in the `level-N.md` files.
- **Evaluation:** tests run on recorded LLM responses. A separate live evaluation scores a run against the answer key and only reports the result; it doesn't block CI.

**Non-goals for v1:** LLM abstraction, detecting contradictions/drift/gaps, diagram-based review, re-ingesting upgraded manuals, PDF and other formats, multiple users and authentication.

**Open questions:** none that block approval. The tech stack, the LinkML ADR, the shared contract versus one contract per dataset, how big a source unit is, and how diagrams are split are left to `/plan`.
